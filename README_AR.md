# Giza PAT System — حزمة المصدر المكتبي والشبكي

هذه الحزمة تجهّز تطبيق Windows باستخدام Electron، مع واجهة المنظومة المرفقة وخدمة مركزية وقاعدة SQLite واحدة على جهاز رئيسي. لا تتضمن الحزمة ملف EXE مبنيًا أو شهادة اختبار ميداني؛ يجب بناء المثبّت على Windows ثم اختبار الأجهزة الخمسة على شبكة الفرع الفعلية.

## مكونات الحزمة
- `index.html`: واجهة المنظومة بعد دمج بطاقات الوحدات الأربع الجديدة مع الإبقاء على الوحدات الحالية، وربط التخزين بالخادم المركزي.
- `main.js` و`preload.js`: تطبيق Electron وإعدادات الاتصال والنسخ الاحتياطي.
- `server.js`: خدمة API وقاعدة SQLite مركزية مع دمج تغييرات السجلات المتزامنة.
- `setup.html`: شاشة ضبط الجهاز الرئيسي والأجهزة العميلة.
- `build_windows.bat`: تثبيت التبعيات وبناء مثبت Windows x64.

## متطلبات البناء
- جهاز Windows 10/11 x64 متصل بالإنترنت أثناء تنزيل التبعيات أول مرة.
- تثبيت Node.js LTS (يفضل 22.x) وGit اختياريًا.
- مساحة كافية لبناء Electron ومكون SQLite الأصلي.

## بناء ملف التثبيت
1. فك ضغط الحزمة في مجلد محلي على جهاز Windows.
2. افتح المجلد `Giza_PAT_Desktop`.
3. انقر بزر الفأرة الأيمن على `build_windows.bat` ثم تشغيل، أو افتح CMD داخله ونفّذ `npm install` ثم `npm run dist`.
4. سيظهر المثبّت داخل `dist` باسم `Giza_PAT_System_Setup_1.0.0.exe`.
5. ثبّت النسخة نفسها على الأجهزة الخمسة.

## إعداد الشبكة الداخلية
1. اختر جهازًا واحدًا فقط ليكون الخادم الرئيسي. يفضّل تثبيت عنوان IPv4 له من الراوتر (DHCP reservation).
2. ثبّت البرنامج على الجهاز الرئيسي، وافتحه، واترك خيار «هذا الجهاز هو الخادم الرئيسي» محددًا.
3. احتفظ بمفتاح الاتصال الذي يظهر في شاشة الإعداد؛ استخدم المفتاح نفسه على الأجهزة الأربعة.
4. على الجهاز الرئيسي افتح Windows Firewall للمنفذ TCP 8765 على شبكة Private فقط. شغّل `allow_firewall_port.bat` بصلاحية مسؤول إن لزم.
5. على كل جهاز عميل أزل علامة «هذا الجهاز هو الخادم الرئيسي»، واكتب `http://IP-الخادم:8765` وأدخل المفتاح نفسه.
6. اترك البرنامج مفتوحًا على الجهاز الرئيسي طوال فترة العمل؛ قاعدة البيانات المركزية تحفظ في `%APPDATA%\giza-pat-system-desktop\data\giza_pat_central.db`.

## اختبار قبول الأجهزة الخمسة (ينفّذ على الشبكة الفعلية)
- شغّل الخادم الرئيسي والأجهزة الأربعة وتأكد أن شاشة المنظومة تفتح على الجميع.
- من الجهاز 1 أضف سجلًا تجريبيًا في وحدة «المعلم المساعد – الدفعة الأولى». من الأجهزة 2–5 ابحث عن الاسم/الكود وتأكد من ظهوره.
- عدّل السجل من الجهاز 2، ثم أعد البحث من الأجهزة 1 و3 و4 و5 وتأكد من ظهور التعديل.
- أضف خمسة سجلات مختلفة بالتزامن من الأجهزة الخمسة، ثم تحقق من عدم فقد أي سجل أو تكرار المعرّفات.
- اختبر التعديل والبحث والاستيراد والتصدير في الوحدات الأربع الجديدة وفي الوحدات القديمة.
- اختبر انقطاع الشبكة: يجب ألا تُدخل بيانات جديدة أثناء انقطاع الخادم؛ أعد الاتصال ثم تحقق من سلامة البيانات.
- خذ نسخة احتياطية، أغلق البرنامج، أعد تشغيل الخادم، ثم تحقق من بقاء السجلات.
- احذف سجلات الاختبار بعد توثيق النتائج. لا تستخدم بيانات شخصية حقيقية قبل اجتياز الاختبار.

## ملاحظات مهمة
- آلية تخزين الواجهة ما زالت تحافظ على واجهة `localStorage` القديمة، لكنها توجه القراءة والكتابة إلى الخادم المركزي. كل عملية حفظ تتم على SQLite؛ يجب إبقاء الخادم متاحًا.
- التعديلات المتزامنة على سجلات مختلفة تُدمج على مستوى السجل. إذا عدّل مستخدمان السجل نفسه في الوقت ذاته، تُعتمد آخر عملية حفظ؛ راجع السجل بعد التعديل في حالات التزامن.
- بيانات الدخول والصلاحيات ما زالت من الواجهة الأصلية، وبها حسابات افتراضية ظاهرة في كود HTML (`admin/1234` و`user/user`). يجب تغييرها/تحصينها قبل الاستخدام الرسمي، ولا تُعد هذه النسخة بعدُ نظام صلاحيات آمنًا للإنتاج.
- حقول الوحدات الأربع الجديدة عامة ومبدئية؛ لا تعتمدها كسجل قانوني نهائي قبل تزويد الحقول الرسمية لكل إجراء.
- ملفات الشعار المنفصلة `logo.png` و`branch_logo.png` لم تكن ضمن المرفق المتاح عند تجهيز هذه الحزمة؛ ستظهر بدائل رمزية عند غياب الشعار.
- لا تفتح المنفذ على الإنترنت العام، ولا تستخدم شبكة Wi-Fi عامة.

## النتيجة الحالية
الحزمة مصدر قابل للبناء والاختبار. لا يمكن من بيئة إعداد Linux هنا إصدار مثبت Windows موثوق أو الادعاء بأن خمسة أجهزة فعلية قد اختُبرت؛ الاختبار المتزامن النهائي يتطلب شبكة الفرع وأجهزتها.

## بناء المثبّت عبر GitHub Actions (دون تثبيت Node.js على جهازك)

أُضيف ملف سير العمل `.github/workflows/build-windows.yml` لبناء مثبت Windows x64 على خوادم GitHub:

1. أنشئ مستودع GitHub **خاصًا (Private)** جديدًا للمشروع.
2. ارفع محتويات مجلد `Giza_PAT_Desktop` إلى جذر المستودع، مع تضمين المجلد المخفي `.github` وملف سير العمل بداخله.
3. من صفحة المستودع افتح تبويب **Actions**، ثم اختر **Build Windows EXE**.
4. اضغط **Run workflow** ثم **Run workflow** مرة أخرى.
5. انتظر انتهاء المهمة بحالة خضراء (Success)، وافتح تشغيل المهمة.
6. من قسم **Artifacts** نزّل `Giza_PAT_System_Setup_1.1.0_Windows_x64`؛ سيحتوي على ملف المثبّت بصيغة EXE.

يمكن أيضًا تشغيل البناء تلقائيًا عند دفع تغييرات إلى فرع `main` أو `master`.

**حماية البيانات:** لا ترفع قاعدة بيانات فعلية أو نسخًا احتياطية أو ملفات تحتوي بيانات موظفين إلى GitHub. تم استبعاد `data/` و`backups/` وملفات قواعد البيانات من Git عبر `.gitignore`. احتفظ بنسخة احتياطية مستقلة ومشفرة قبل أي تجربة تثبيت أو ترقية. لا تضع مفاتيح أو كلمات مرور حقيقية داخل المستودع.

**حدود هذه الخطوة:** إضافة سير العمل إلى المصدر لا تعني أن ملف EXE قد بُني بالفعل. البناء الفعلي يبدأ بعد رفع المصدر إلى مستودع GitHub وتشغيل المهمة، ثم يجب اختبار المثبّت على جهاز Windows قبل استخدامه على أجهزة الفرع.
